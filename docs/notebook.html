Fraude par carte bancaire

Quelles transactions vérifier en priorité ?

Une équipe peut examiner 20 paiements sur 10 000. Elle peut choisir les opérations les plus probablement frauduleuses, ou privilégier celles qui exposent les montants les plus élevés. Sur les mêmes paiements, quel choix repère le plus de fraudes ? Quel choix couvre le montant frauduleux le plus élevé ?

1. Retrouver le problème du mémoire

Le mémoire comparait sept familles de modèles et plusieurs techniques de rééchantillonnage. Dans les sorties de 2020, deux réseaux entraînés avec ADASYN, une méthode qui crée des exemples synthétiques de la classe rare, donnaient des résultats différents sur les mêmes 98 fraudes.

Le premier repérait trois fraudes de plus et demandait quatorze vérifications supplémentaires. Ces deux matrices décrivent les seuils utilisés à l'époque. Elles ne donnent pas les transactions qu'aurait choisies chaque modèle avec un plafond de vingt contrôles.

Pourquoi refaire le test ? Le carnet historique appliquait au tableau complet des positions calculées sur un sous-ensemble. Des transactions réservées au test pouvaient entrer dans l'entraînement. La standardisation du montant précédait aussi la séparation. Ici, toutes les transformations apprises utilisent la période prévue et le test final intervient après la sélection du modèle.

Source historique : mémoire, pages imprimées 54, 56 et 63, et sorties conservées dans le carnet principal de l'archive.

def empreinte(fichier):
    h = hashlib.sha256()
    with fichier.open("rb") as flux:
        for bloc in iter(lambda: flux.read(1024 * 1024), b""):
            h.update(bloc)
    return h.hexdigest()


def trouver_csv(chemin):
    if chemin:
        fichier = Path(chemin).expanduser()
        if not fichier.is_file():
            raise FileNotFoundError(f"CSV introuvable au chemin choisi : {fichier}")
        return fichier
    candidats = [Path("data/creditcard.csv"), Path("creditcard.csv")]
    for fichier in candidats:
        if fichier.is_file():
            return fichier
    cible = candidats[0]
    cible.parent.mkdir(parents=True, exist_ok=True)
    with NamedTemporaryFile(dir=cible.parent, suffix=".part", delete=False) as temporaire:
        partiel = Path(temporaire.name)
    try:
        with urlopen(SOURCE_CSV, timeout=90) as flux, partiel.open("wb") as sortie:
            copyfileobj(flux, sortie)
        if empreinte(partiel) != SHA256_MIROIR:
            raise ValueError("Le téléchargement diffère de la copie vérifiée. Vérifie la source.")
        partiel.replace(cible)
    finally:
        partiel.unlink(missing_ok=True)
    return cible

4. Apprendre et vérifier un score de fraude

La régression logistique sert de référence. Le réseau de neurones possède deux couches cachées de 32 et 16 neurones. Il reprend une idée du mémoire de 2020 avec une architecture plus compacte. Un troisième candidat, le boosting d’arbres, apprend des règles non linéaires en corrigeant successivement les erreurs des arbres précédents.

Pour comparer ces modèles à coût de calcul modéré, on garde toutes les fraudes de l’entraînement et jusqu’à 30 paiements légitimes par fraude. Les trois modèles reçoivent exactement les mêmes lignes. Ce choix réduit la diversité des opérations légitimes vues à l’entraînement. Les périodes de calibration, de validation et de test conservent tous leurs paiements.

Calibrer les probabilités

Une probabilité de 10 % devrait correspondre à environ 10 fraudes pour 100 paiements comparables. Comme nous avons modifié la fréquence des fraudes à l’entraînement, on réajuste les probabilités sur la période de calibration, à la fréquence observée. La méthode de Platt apprend une régression logistique à une variable sur les scores du modèle. On vérifie ensuite ce réglage sur la période de validation, plus tardive.

Deux mesures guident la lecture. La précision moyenne (Average Precision, AP) évalue la qualité du classement des fraudes vers le haut de la liste. Le score de Brier mesure l’erreur quadratique entre la probabilité prédite et l’étiquette réelle. Une AP élevée et un Brier faible sont préférables.

estimateurs = {
    "Régression logistique": LogisticRegression(max_iter=600, random_state=graine_modele),
    "Réseau à deux couches": MLPClassifier(
        hidden_layer_sizes=(32, 16), activation="relu", solver="adam",
        batch_size=min(128, len(positions)), max_iter=150, n_iter_no_change=12,
        learning_rate_init=0.001, random_state=graine_modele
    ),
    "Boosting d’arbres": HistGradientBoostingClassifier(
        max_iter=100, max_leaf_nodes=15, l2_regularization=1.0,
        early_stopping=False, random_state=graine_modele
    ),
}

def score_logit(probabilites):
    # Bornes numériques pour les modèles qui renvoient exactement zéro ou un.
    p = np.clip(np.asarray(probabilites), 1e-12, 1 - 1e-12)
    return (np.log(p) - np.log1p(-p)).reshape(-1, 1)

modeles_ajustes = {}
scores_validation = {}
lignes_validation = []

for nom, estimateur in estimateurs.items():
    modele = make_pipeline(StandardScaler(), estimateur)
    modele.fit(X_apprentissage, y_apprentissage)

    p_cal_brut = modele.predict_proba(X_cal)[:, 1]
    calibrateur = LogisticRegression(C=1.0, max_iter=500)
    calibrateur.fit(score_logit(p_cal_brut), y_cal)

    p_val_brut = modele.predict_proba(X_val)[:, 1]
    p_val = calibrateur.predict_proba(score_logit(p_val_brut))[:, 1]
    modeles_ajustes[nom] = (modele, calibrateur)
    scores_validation[nom] = p_val
    lignes_validation.append({
        "Modèle": nom,
        "AP": average_precision_score(y_val, p_val),
        "Brier brut": brier_score_loss(y_val, p_val_brut),
        "Brier calibré": brier_score_loss(y_val, p_val),
    })

# Règle fixée pour la sélection : AP d’abord, puis Brier calibré en cas d’égalité.
comparatif_validation = pd.DataFrame(lignes_validation).sort_values(

Le niveau de risque annoncé correspond-il aux fréquences observées ?

On regroupe les probabilités de validation du modèle retenu. Pour chaque tranche, on compare le risque moyen annoncé à la proportion de fraudes observée. 5. Décider quelles transactions vérifier

Expérience principale. À la clôture de chaque lot chronologique de 10 000 paiements, une équipe peut instruire 20 alertes. Quel classement lui permet de repérer le plus grand montant de fraude ?

  • Risque seul privilégie les probabilités de fraude les plus élevées.
  • Risque × montant privilégie les montants frauduleux attendus les plus élevés, en multipliant la probabilité par le montant du paiement.

Les deux stratégies reçoivent les mêmes probabilités et le même budget. Pour le dernier lot incomplet, on arrondit le nombre de contrôles à l’entier inférieur. L’identifiant de ligne départage les scores identiques. Les scénarios de 10 et 40 contrôles sont des analyses de sensibilité prévues à l’avance. La comparaison simule une revue par lots.

Mesurer les deux sélections

On révèle maintenant le statut des transactions. La précision donne la part de fraudes parmi les alertes vérifiées. Le rappel donne la part des fraudes repérées parmi toutes les fraudes du test. La couverture monétaire donne la part du montant frauduleux total qui se trouve dans les alertes. Chaque pourcentage global est calculé à partir des totaux. Un dénominateur nul laisse le pourcentage indéfini.

Voir le code PythonReplier le code Python de la cellule 27
def bilan_controles(alertes):
    controles = len(alertes)
    vraies = alertes.loc[alertes["Class"].eq(1)]
    return {"contrôles": controles, "fraudes repérées": len(vraies),
            "fausses alertes": controles - len(vraies), "montant repéré": vraies["Amount"].sum()}

par_lot = []
for (politique, budget), alertes in files_alertes.items():
    for lot, donnees_lot in paiements.groupby("lot", sort=True):
        choisies = alertes.loc[alertes["lot"].eq(lot)]
        vraies = donnees_lot.loc[donnees_lot["Class"].eq(1)]
        assert len(choisies) == len(donnees_lot) * budget // TAILLE_LOT
        par_lot.append({"budget": budget, "stratégie": politique, "lot": lot,
                        "paiements": len(donnees_lot), "fraudes du lot": len(vraies),
                        "montant frauduleux du lot": vraies["Amount"].sum(),
                        **bilan_controles(choisies)})

6. Reproduire et prolonger l'étude

Le rappel est la proportion des fraudes réelles retrouvées. La précision est la proportion des alertes qui sont effectivement frauduleuses. La couverture en montant est la part du montant total des transactions frauduleuses comprise dans la sélection. Une banque aurait besoin d'informations supplémentaires sur les remboursements, les délais de traitement et les frais d'enquête pour chiffrer une perte nette réellement évitée.

Les deux jours de septembre 2013 ne permettent pas d'établir la stabilité du classement à long terme. La validation ne comporte que 27 fraudes et les très gros paiements peuvent peser fortement sur les montants cumulés. Une suite scientifique consisterait à rejouer le protocole sur d'autres périodes indépendantes, puis à mesurer l'effet du délai de confirmation des fraudes.
